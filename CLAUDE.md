# Guitar — monorepo for guitar training tools

## Repository structure

Each sub-project lives in its own directory (e.g. `fretforge/`). Shared principles apply across all projects.

## Git workflow

- `main` — production branch, no Claude/harness config files committed
- `develop` — development branch, may include `.claude/` config files
- Commit messages in English, concise, describing the "why" not the "what"

## What goes into git (and what doesn't)

**Commit:**
- Source code (`src/`, `*.ts`, `*.tsx`, `*.css`, `*.html`)
- Config files (`package.json`, `tsconfig.json`, `vite.config.ts`, etc.)
- Lock files (`package-lock.json` — ensures reproducible installs)
- Project-level docs (`CLAUDE.md`, `README.md`)

**Do NOT commit:**
- `node_modules/` — restored via `npm install`, locked by `package-lock.json`
- `dist/` — generated by `npm run build`, derives from source
- `.env` / credentials — secrets never touch git

Principle: **source in, artifacts out.** If something can be deterministically regenerated from committed files, it doesn't belong in git.

## Frontend stack

- React 18 + TypeScript
- Vite for dev/build
- Vitest for tests
- Plain CSS with custom properties for theming (no CSS framework)
- Dual audio engine pattern: Web Audio API (desktop) → HTML5 `<audio>` (iOS fallback)

## Conventions

- Logic in hooks (`src/hooks/`), presentation in components (`src/components/`)
- Components receive data via props, don't fetch or manage business state
- CSS variables defined in `src/index.css` under `:root`
- Keyboard shortcuts handled at `App.tsx` level
